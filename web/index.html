The number is weighted rule coverage, not a probability. 0.82 means fourteen of seventeen weight units are satisfied — it is not an 82% chance of success, and nothing here should be read that way. The rules check structure, not truth: a handoff can cite a real file, score strong, and still be wrong about what that file does.

This page runs the same rules as crumblm score, from web/crumb-score.js in the repository — a parity test asserts, signal by signal, that it agrees with the Python implementation on every CRUMB the project ships.
